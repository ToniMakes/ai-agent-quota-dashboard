# Product and Technical Brief

Last updated: 2026-09-16

AI Agent Quota Dashboard, or AIQD, is a local-first desktop dashboard for viewing quota windows reported by AI coding tools. It focuses on remaining quota, reported reset timing, freshness, and source confidence. It is a monitoring tool, not an account manager or an authentication client.

## Product scope

The first public preview focuses on Codex and Claude on Windows. The application includes:

- A dashboard for current quota and reset information
- Diagnostics and setup guidance for supported local sources
- A tray mini panel and an always-on-top widget
- Local refresh history, reset events, and JSON or CSV export
- An Electron desktop shell and an installer-first Windows distribution
- English by default, with Chinese and English UI support

If a trustworthy local source is unavailable, AIQD reports that state instead of guessing.

## Supported local sources

AIQD reads narrow quota-related data from tools already used by the user:

- Codex CLI structured local `rate_limits` events, with an explicitly labeled manual fallback
- Claude Code official statusline rate-limit data through a local receiver
- Claude Desktop local plan usage history, as an alternative to Claude Code

Claude Desktop and Claude Code are alternative sources for the Claude view. Users do not need to install or configure both.

The application does not monitor browser-only use of products such as `claude.ai` or `chatgpt.com`, because browser sessions do not provide a supported local quota source.

## Privacy and security boundary

AIQD is designed to keep quota data on the user's computer:

- The local service binds to loopback, normally `127.0.0.1`
- Normalized quota snapshots and refresh history are stored in local SQLite
- The app does not read browser cookies, passwords, prompts, responses, source code, or chat content
- The app does not simulate login, switch accounts, bypass limits, or call hidden provider APIs
- Public exports omit local source references and account identifiers
- The website is a static product page and does not receive quota data from the desktop app

See [Privacy](privacy.md) for the detailed data boundary and [Security](../SECURITY.md) for vulnerability reports.

## Technical shape

The project uses TypeScript and Node.js for the local service and CLI, SQLite for local persistence, and Electron for the desktop shell. The browser surfaces use the same local HTTP service and relative `/api/` routes. The Windows installer is built with `electron-builder` and NSIS.

The public repository includes unit tests, desktop smoke checks, CI on Windows and Ubuntu, pinned GitHub Actions, dependency auditing, and an SBOM workflow. Release artifacts are generated by GitHub Actions from version tags and include a SHA256 sidecar file.

## Release model

The public distribution is installer-first for Windows. Source mode remains available for developers who want to inspect or run the project locally. The v0.1.0 preview is unsigned while the open-source signing path is pending, so release notes clearly state the signature status and provide the installer checksum.

The published installer may lag behind fixes that have landed on `main`. Always use the release asset and release notes for the exact downloadable build, and use the repository history to inspect newer development changes.

## Design principles

1. Prefer an honest unavailable or stale state over a guessed quota value.
2. Read the smallest local data surface needed for quota monitoring.
3. Keep setup explicit, reversible, and visible to the user.
4. Treat local observations as observations, not guarantees about provider policy.
5. Keep public documentation free of account data, raw logs, local user paths, credentials, and private deployment details.

## Deferred scope

The project intentionally defers additional providers, cloud sync, team management, browser automation, account switching, and guaranteed provider-wide usage reporting. These features require reliable data sources and must preserve the local-first privacy boundary before they are considered.
